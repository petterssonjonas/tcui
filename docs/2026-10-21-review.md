## 1. Security

Most of the security-sensitive code is in good shape and should be left alone: the key store
(`src/config/key_store/`, O_NOFOLLOW opens, 0600 temp files, rename + fsync, rollback), the OAuth
flows (PKCE S256, 127.0.0.1-only callback listener, constant-time state compare, https-only
endpoints, redaction in Debug/Display), MCP child processes (`env_clear` plus an allow-list, one API
key per server), and the memory store path confinement. The findings below are the exceptions.

### SEC-1. `restore_note` reads an arbitrary local file into the vault — High, CONFIRMED
- Files: `src/skill_runtime.rs:553-569`
- Problem: the model-controlled `backup` argument is joined onto the backup directory without
  validation (`backup_dir.join(backup)`). `Path::join` with an absolute path replaces the base, and
  `..` components walk out of it. Only `path` goes through `validate_vault_path`.
- Scenario: user types `@obsidian restore my notes` (the "restore" keyword satisfies `authorize_tool`);
  a hostile or compromised model/provider answers with
  `{"tool":"restore_note","arguments":{"path":"notes/x.md","backup":"/home/user/.ssh/id_ed25519"}}`.
  The private key is written into a vault note, which is usually cloud-synced and readable by the
  model on the next `@obsidian read`.
- Fix: reject `backup` values that are absolute, contain `..`, or have more than one path component;
  require the backup naming pattern the writer produces; canonicalize and assert `starts_with(backup_dir)`.
- Done when: a unit test with an absolute and a `../` backup argument returns an error and writes nothing.

### SEC-2. Markdown links from model output are opened with `xdg-open`/`open` with no scheme filter — Medium, CONFIRMED
- Files: `src/app.rs:451-470` (`open_external_target`), link source `src/ui/components/markdown_model.rs:591`
- Problem: any `dest_url` the assistant emits becomes a clickable target and is handed verbatim to the
  desktop URL handler. `file://`, `vscode://`, `ssh://`, or any registered `x-scheme-handler` runs
  with attacker-chosen arguments; a target starting with `-` is parsed as an option by `xdg-open`.
- Fix: allow only `http`, `https`, `mailto` (plus the internal `skill:`); reject targets starting with
  `-`; show the real destination in the status/toast before or while opening.
- Done when: clicking a `file:///etc/passwd` link shows a "blocked" toast and spawns nothing.

### SEC-3. Model-emitted `<tcui:remember>` directives persist automatically and are re-injected into every later chat — Medium, PLAUSIBLE (design)
- Files: `src/memory/directive.rs:69-95`, `src/app/runtime.rs:824-840`, `src/memory/host.rs:144-155`
- Problem: untrusted content (web search, MCP result, vault note) can get the model to emit a remember
  tag; `capture()` stores it after only a `likely_secret` keyword filter, and `recall()` injects it
  into future prompts. This is persistent cross-conversation prompt injection.
- Fix: require an explicit accept (toast with accept/reject, or the next-turn confirmation) before
  capture when the turn contained tool/search data, or make auto-capture an opt-in setting.
- Done when: a memory produced in a turn that used search/MCP/vault input is not stored without a user action.

### SEC-4. Vault `read_file`/`write_file` follow symlinks inside the vault — Medium, PLAUSIBLE
- Files: `src/obsidian/vault.rs:34-45`; callers `src/skill_runtime.rs:506,550,567`, `src/app/artifacts.rs:185`
- Problem: `validate_vault_path` rejects `..` and absolute paths only. A symlink inside the vault
  (planted by sync, a share, or an earlier write) pointing at `~/.bashrc` passes validation and
  `write_note` truncates the target.
- Fix: canonicalize `root.join(path)` and require `starts_with(canonical_root)`; write via
  `create_new` temp + rename, as the memory store does.
- Done when: writing through a symlink that leaves the vault returns an error.

### SEC-5. Self-updater and install script trust unsigned artifacts and a racy temp dir — Medium, PLAUSIBLE
- Files: `src/updater.rs:65-74,118,126-135`, `src/updater/platform.rs:12-18`, `scripts/install.sh:79-87`
- Problem: `SHA256SUMS` comes from the same release as the binary (integrity only, no authenticity);
  `asset_url` from the GitHub API JSON is not required to be on `github.com`; the temp dir is created
  with `create_dir_all` (succeeds on a pre-existing attacker-owned dir) and files are written with
  `fs::write` (follows symlinks); `install.sh` warns and continues when `SHA256SUMS` is missing.
- Fix: `create_dir` with mode 0700 and fail if it exists; check the asset host; sign `SHA256SUMS`
  (minisign/cosign) and verify in both the updater and the script; make `install.sh` fail closed.
- Done when: the updater refuses a pre-existing temp dir and a non-github asset URL; `install.sh` exits non-zero without checksums.

### SEC-6. Argument injection into `ddgr` and `notify-send` — Low, CONFIRMED
- Files: `src/search.rs:36-39`, `src/notifications.rs:84-90`
- Problem: the model-rewritten search query and the first line of the model's answer are passed as
  positional args with no `--` separator; a value starting with `-` is parsed as an option
  (`--proxy`, `--url-handler`, `-u critical`, `--action=`).
- Fix: insert `"--"` before user/model-derived arguments, or reject leading `-`.
- Done when: a query of `--version` is searched literally rather than executed as a flag.

### SEC-7. Unknown providers are trusted unconditionally, including plain `http://`; `.env` is read from the current directory — Low, CONFIRMED (design)
- Files: `src/llm/auth/policy.rs:46` (`_ => true`), `src/llm/auth/reader.rs:80`
- Fix: require `https` for non-loopback custom endpoints; read only `~/.env`, or require an opt-in for `./.env`.
- Done when: a custom provider with `http://example.com` is refused a bearer token unless the host is loopback.

### SEC-8. Skills are loaded from the current directory and other tools' directories without integrity checks — Low, CONFIRMED
- Files: `src/skills/catalog.rs:18-22,41-50`
- Problem: `./skills/*/SKILL.md` from whatever directory tcui is launched in becomes system-prompt
  context on `@mention`; `~/.codex/skills` and `~/.config/opencode/skills` are other tools' trust
  domains. `skills-lock.json` in the repo root is not read by tcui at all.
- Fix: drop CWD discovery or require a per-project opt-in; optionally hash-pin against a lock file.

### SEC-9. Release builds honor `TCUI_AUTH_TEST_SIGNAL_READY` and create/truncate that path — Low, CONFIRMED
- Files: `src/auth_command/runner.rs:19,63-66`
- Fix: gate with `#[cfg(any(test, debug_assertions))]`.

### SEC-10. Minor file-handling items — Low, CONFIRMED
- `src/app/input.rs:244-250`: chat draft written to `$TMPDIR` with default perms via `fs::write` (follows symlinks). Use the 0700 data dir or `create_new().mode(0o600)`.
- `src/llm/chat.rs:338-347`: SSE buffer for OpenAI-compatible/Anthropic streams is unbounded; the Codex transport caps at 2 MiB (`codex_responses/transport.rs:19-24`). Reuse `TransportLimits`.
- `src/reminders/store.rs:49`, `src/storage/crypto.rs:194-197`, `src/diagnostics.rs:36-47`: non-atomic or default-permission writes. Route through the existing atomic writer.
- `src/storage/crypto.rs:134-136`: `decrypt_shared_text_with_key` returns un-enveloped plaintext as-is, which masks accidental plaintext persistence. Reject after the migration window.
- `src/notifications.rs:55-63,93-101`: ntfy defaults to `http://` and has no client timeout.
- `src/llm/auth/reader.rs:13-23`: Gemini token files are read without the owner/mode check applied to Codex (`codex/credential.rs:171-202`).

## 2. Settings system design

Current shape: `AppConfig` (TOML at `~/.config/tcui/config.toml`, `src/config/app_config.rs`) is
loaded into `Arc<tokio::sync::RwLock<AppConfig>>` on `TuiApp`; ~15 of its fields are copied into
`UI` at startup (`src/app.rs:56-78`); the "settings panel" (`src/tui/settings_panel.rs`, opened by
`/settings`, `Ctrl+,`, `Ctrl+S` and three different actions) is a static searchable catalog of 37
rows of which only four kinds do anything: run a command, pick a theme, pick a toast position, and
toggle two booleans. The old six-tab `SettingsPopup` described in `docs/ui-refactor-plan.md` §1.8 is
gone; the schema-driven editing that was to replace it (plan §C, "SettingRegistry") was never built.
The SQLite `settings` table and `get/set/get_all_settings` are dead. The findings below are ordered
by how much damage they can do.

### SET-1. Every `AppConfig::load()` rewrites `keys.toml` and wipes the legacy `keys` map — High, CONFIRMED
- Files: `src/config/app_config.rs:392-406` (`bootstrap_xdg_layout`), `src/config/key_store.rs:52-67` (`save_keys`)
- Problem: `bootstrap_xdg_layout` runs on every `load()` and calls `KeyStore::save_keys(config, &[])`,
  which loads the key file, does `file.keys.clear()`, and writes it back. `load()` is called at
  startup (`main.rs:173`), by `Storage::new` (`db.rs:106`), on **every credential resolution**
  (`llm/auth/resolver.rs:42`), on every Codex request (`llm/codex_responses.rs:42`), in the auth CLI
  and the memory MCP server. Consequences: (a) any entry in the legacy `keys` map is destroyed on the
  first run of this version, so `KeyStore::get` (`resolver.rs:99`, `auth/legacy.rs:26`,
  `mcp/transport.rs:122`) can never return a value and the `CredentialSource::LegacyKeyStore` and
  MCP `key_store` lookups are dead; (b) the secrets file is rewritten (temp, rename, fsync) on every
  chat request, and the write guard is a process-local mutex, so a concurrent `tcui auth` and TUI
  race on it.
- Fix: make `load()` side-effect free. Move directory/file bootstrap into an explicit
  `ensure_layout()` called once from `main`, and have it create `keys.toml` only if missing (an
  `ensure_exists` on `KeyStore`, not `save_keys`). Decide the legacy `keys` map's fate: either
  migrate entries into `credentials` once, or delete `KeyStore::get`, `save_keys`,
  `LoadedKeysFile::keys`, the `LegacyKeyStore` source and the MCP `key_store` field.
- Done when: a test seeds `keys.toml` with a `keys` entry, calls `AppConfig::load()` twice, and the
  file is byte-identical afterwards; `strace`/a counter shows no key-file write during a chat request.

### SET-2. `load()` rewrites `config.toml`, dropping unknown keys, comments, and the `[memory]` section in non-memory builds — High, CONFIRMED
- Files: `src/config/app_config.rs:313-320,408-415` (`rewrite_if_migrated`), field at `:258-259`
- Problem: `rewrite_if_migrated` re-serializes the struct and overwrites the file whenever the parsed
  TOML differs from the canonical form. `AppConfig` has no `deny_unknown_fields` and no catch-all, so
  every unknown or future key and every comment is silently deleted. The `memory` field exists only
  under `#[cfg(feature = "memory")]`, so running a build without the feature deletes the user's whole
  `[memory]` table.
- Fix: never write on load. If alias migration (`kitty_text_max_scale`) must be persisted, set a flag
  during deserialization and rewrite only then, using `toml_edit` to preserve comments. Keep `memory`
  in the struct unconditionally (gate its *use*, not its presence) and add
  `#[serde(flatten)] extra: toml::Table` to round-trip unknown keys.
- Done when: a config with a comment, an unknown key and a `[memory]` table survives `load()` unchanged in both feature builds.

### SET-3. Config mutation pattern can persist a default config and never reports lock failures — High, CONFIRMED (latent)
- Files: `src/app/settings.rs:8-16,27-35,43-51`, `src/app/runtime.rs:1012-1020`, `src/app.rs:56`,
  `src/app/providers.rs:117`, `src/app/connection.rs:26`, `src/app/popups.rs:56`, `src/app/runtime.rs:481`,
  `src/app/input_events.rs:53-55,62-64,105-107`, `src/app/export.rs:142`
- Problem: nine sites do `self.config.try_read().map(clone).unwrap_or_default()`, mutate one field,
  `save()`, then `try_write()` and ignore failure. If a read guard is ever held across an await, a
  single toggle writes `AppConfig::default()` (default providers, no vault, no local inference) to
  disk. `export.rs:142` uses `blocking_read()` inside the async dispatch path, which panics under
  tokio ("Cannot block the current thread from within a runtime"); reachable via artifact sidebar →
  Memory → Export → Enter. The `Arc<RwLock>` is never cloned or shared with any task, so the lock
  buys nothing today.
- Fix: own `AppConfig` by value on `TuiApp`. Add one method,
  `fn update_config(&mut self, f: impl FnOnce(&mut AppConfig)) -> Result<()>` that mutates, saves
  atomically (temp + rename), and calls `apply_config_to_ui()` (SET-12). Replace every site above.
- Done when: `grep -rn "unwrap_or_default" src/app` finds no config snapshot; `blocking_read` is gone.

### SET-4. Settings panel booleans do not reflect the real config — High, CONFIRMED
- Files: `src/tui/settings_panel.rs:843-844` (`T::Bool { enabled: false }` / `{ enabled: true }`), `:142,368-378` (`bool_toggles`), `src/app/runtime.rs:198,211,404,410` (`SettingsPanelState::new()` on every open)
- Problem: the catalog is static, the checkbox state lives in a per-panel `HashMap` that is created
  empty each time the panel opens, and nothing reads `AppConfig`. A user with `web_search.enabled =
  true` opens the panel, sees "○ Web Search" (off), presses Enter, the real value flips to off while
  the row shows "✓".
- Fix: build rows from `&AppConfig` (pass current values into `all_settings(&config)` or resolve
  `enabled` at render/enter time via a getter) and delete `bool_toggles`.
- Done when: the rendered check mark equals the config value before and after toggling, covered by a `TestBackend` test.

### SET-5. Settings Enter handling is duplicated with divergent behaviour — Medium, CONFIRMED
- Files: `src/app/input_events.rs:127-175` (keyboard), `src/app/runtime.rs:957-1008` (mouse `select_settings_item`)
- Problem: the same `match settings.enter()` exists twice. Keyboard swallows `apply_theme_selection`
  errors with `let _ =` and emits `Action::ToggleWebSearch`; mouse calls `toggle_web_search()` directly
  and pushes its own toast. Any new setting kind must be added in both.
- Fix: keyboard path emits `Action::ActivateSetting(index)` (or `(id)`); runtime handles it once.
- Done when: one match arm per `EnterResult` exists in the codebase.

### SET-6. Two command registries, four "open settings" actions, and a command palette that is never shown — Medium, CONFIRMED
- Files: `src/tui/palette.rs` (557 lines, `PaletteState` is never constructed outside tests; `ui.palette` is never `Some`),
  `src/app/input_events.rs:81-121` (dead palette key branch), `src/app/action.rs` (`SetPinnedCommands`, `SelectPaletteItem`, `OpenCommandPalette`, `ShowSettings`, `CloseSettings`, `ToggleSettings`, `OpenSettingsPanel`),
  `src/tui/settings_panel.rs:811-822` (second command table), `src/config/tui.rs` (`pinned_commands`)
- Problem: `palette::all_commands()` (18 entries, with shortcut labels that are not derived from the
  real key handler) and the settings panel's Commands section (12 entries) have drifted; the panel's
  title is "Command Palette" while the real `PaletteState` is dead code; `OpenCommandPalette` opens
  the settings panel. `tui.pinned_commands` is written to every user's config for a feature that
  cannot be reached.
- Fix: one `CommandRegistry` (id, label, keywords, default shortcut, `Action`) consumed by the settings
  panel Commands section, the keybind table (SET-8), `/help`, and the slash-command table
  (`input_events.rs:5-16` and `:649-656` and `app.rs:393-405` are three more copies). Delete
  `palette.rs`, the palette key branch, `SetPinnedCommands`, `SelectPaletteItem`, `pinned_commands`.
  Collapse `ShowSettings`/`ToggleSettings`/`OpenCommandPalette`/`OpenSettingsPanel` into one toggle action.
- Done when: the command list shown in the panel, `/help`, and the slash-command parser come from the same table.

### SET-7. Most of the config surface has no in-app editor; the panel's Text/Number/Choice kinds are stubs — Medium, CONFIRMED
- Files: `src/tui/settings_panel.rs:78-95,285-287` (`Text | Number | Choice(_) => EnterResult::Nothing`), `src/config/app_config.rs:230-262`
- Problem: only theme, toast position, `web_search.enabled` and `collapse_thinking` are editable in
  the UI. `default_provider`, `default_model`, alignments, `markdown_mode`, `vault_path`,
  `artifact_save_dir`, `local_inference.*`, `providers`, `mcp_servers`, `notifications`,
  `kitty_heading_downscale`, `show_selector`, `show_chat_scrollbar`, `quit_confirmation`,
  `image_protocol` require editing `config.toml` by hand, and there is no reload command, so a
  restart is needed. Nine of 13 `SettingCategory` variants are unused.
- Decision needed (recommendation first): (a) finish the schema-driven design from
  `docs/ui-refactor-qna.md` §C with one table
  `SettingDef { id, title, category, kind: Bool|Enum(&[..])|Text|Path|Number{min,max}, get: fn(&AppConfig) -> Value, set: fn(&mut AppConfig, Value) -> Result }`
  that drives search, rendering, Enter, validation and persistence; or (b) declare `config.toml` the
  editor, add `/reload`, rename the panel to "Commands", and delete the stub variants and categories.
- Done when: either every `AppConfig` field reachable from the panel round-trips through `set`/`get`
  with a test per kind, or the stub variants no longer exist and the docs say "edit config.toml".

### SET-8. Keybinding overrides are persisted but never consulted — Medium, CONFIRMED
- Files: `src/app/input_events.rs:25-74` (capture flow, with a TODO saying dispatch ignores overrides),
  `src/tui/keybind_capture.rs` (288 lines), `src/tui/settings_panel.rs:885-910` (`keybind()` builder, unused),
  `src/config/tui.rs` (`keybinding_overrides`), `src/ui/mod.rs:817-830`

- Fix: either route `handle_key` through a `Keymap` built from registry defaults + overrides (then
  re-add Keybind rows), or delete the capture module, the overrides field and the mirrors.
- Done when: an override in `config.toml` changes behaviour, or the field no longer exists.

### SET-9. Two sources of truth for providers and MCP servers; five dead SQLite tables — Medium, CONFIRMED
- Files: `src/storage/db.rs:104-108,404-439` (`sync_providers` deletes DB rows absent from config on every `Storage::new`),
  `:365-400` (`update_provider`/`delete_provider`/`add_provider`, no callers), `:179-215` (`settings` accessors, no callers),
  `migrations/init.sql` (`settings`, `tabs`, `file_backups`, `mcp_servers`, `key_metadata` never queried), `migrations/001_initial.sql` (never included)
- Problem: `config.providers` is authoritative and the DB `providers` table is a derived cache, but
  the Storage API still exposes mutators that would be silently reverted on the next start.
  `config.mcp_servers` is authoritative while an `mcp_servers` table exists unused. `tab_configs`

- Fix: delete the dead mutators, the `settings` accessors, `001_initial.sql`, and `tab_configs`.
  Keep `providers`/`models` tables only as the model cache, or move the cache to a file keyed by provider name.
  Add a `PRAGMA user_version` migration that drops the unused tables (see CQ-9).
- Done when: `init.sql` only creates tables that have at least one `SELECT` in `src/`.

### SET-10. Config fields that are serialized into every user's file but never read — Low, CONFIRMED
- Files: `src/config/app_config.rs`
- `tab_configs`, `small_model`, `use_env_keys`, `local_inference.model_directory`,

  `tui.pinned_commands`, `tui.keybinding_overrides`: see SET-6 / SET-8.

### SET-11. Config persistence is not atomic and falls back to the current directory — Low, CONFIRMED

- Fix: write temp + rename through the same helper the key store uses; return an error when the config dir is unknown; simplify the signatures to `PathBuf`.
- Done when: killing the process mid-save cannot leave a truncated `config.toml`.

### SET-12. UI mirrors of config are updated by hand and drift — Low, CONFIRMED

## 3. Correctness and code quality

Live code is `src/app/` + `src/ui/`; `src/tui/` is the partially adopted namespace from the refactor
plan (`shell.rs`, `settings_panel.rs`, `keybind_capture.rs`, `status_bar*.rs`, the `Focus` enum are
used; `palette.rs`, `FocusStack`, most of `components.rs` are scaffolding). Items marked "verified"
were re-checked by the lead reviewer after the delegated pass.

### CQ-1. `generate_title` byte-slices user text and panics on non-ASCII — High, CONFIRMED (verified)
- `src/app.rs:482-483`: `&title[..16]` on the first five words of the first message. A first message
  such as `Привет мир как дела` puts byte 16 inside a multi-byte char and the whole app panics.
- Fix: truncate by `chars().take(16)` or `floor_char_boundary`; add a test with Cyrillic/CJK/emoji input.

### CQ-2. `blocking_read` inside the async dispatch path — High, CONFIRMED (verified)
- `src/app/export.rs:142`. Panics under tokio. Reachable from the memory export dialog. Covered by SET-3's fix.

### CQ-3. Streaming writes into whatever conversation occupies `tab.messages[idx]` — High, CONFIRMED
- `src/app/runtime.rs:236-267` (`StreamResponse`/`FinalizeAssistantMessage`), `src/ui/mod.rs:937-960`,
  `src/app/conversations.rs:49-61` (`reset_tab_runtime_state` clears messages but not `streaming`).
- Scenario: send in chat A, click chat B in the sidebar during the stream; if B has an assistant
  message at the same index it receives A's tokens, and `persist_active_conversation` writes A's
  answer into B's file.
- Fix: carry `conversation_id` in stream actions and drop events whose id is not the active one;
  keep a per-tab `JoinHandle`/`CancellationToken` and abort on load/new/delete. Pair with CQ-12.

### CQ-4. Ctrl+E is intercepted before the overlay branches — High, CONFIRMED (verified)
